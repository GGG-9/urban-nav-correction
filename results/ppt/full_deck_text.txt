1.1  Why a Three-Tier Architecture?
PART ONE · OVERVIEW & BACKGROUND
Simulated IMU / GNSS corpus · 48 routes · 8.64 M rows · 8 held-out test routes
Urban navigation correction · Guo Haisu
Each tier removes what the one before cannot — physics, then compute, then learned and spatial information.
MEMS IMU / AHRS and GNSS antenna — the sensor class this pipeline targets.
TIER 1
Physical filtering & smoothing (ESKF + RTS)
A 15-state filter fuses 100 Hz IMU with 1 Hz GNSS; an RTS pass then uses the post-outage fixes. Outage error 104.65 m → 9.93 m (−90.5 %).
TIER 2
GPU window-batched parallelism
192 windows from 48 routes in one batch on a single RTX 4090. 1 M IMU rows in 46.2 s instead of 2,245 s; the whole 8.64 M-row corpus in 17 minutes.
TIER 3
Learned residual and a map prior
A LoRA-tuned DistilGPT2 reads 20-channel tensors and is admitted only through a one-standard-error gate. A road-centreline prior then takes B3 from 9.93 to 6.30 m.

Mechanization turns bias-corrected IMU measurements into attitude, velocity and position.
INPUTS
Bias-corrected IMU
Local ENU gravity
Subtract the biases before integration; normalise the quaternion after every attitude update.
OUTPUTS
Attitude q, velocity v, position p at 100 Hz — the nominal state the error filter later corrects.
1
Update attitude from the angular rate
Quaternion exponential of the bias-corrected gyro, normalised at every step.
2
Rotate specific force and update velocity
Body-frame specific force rotated into ENU, gravity removed, then integrated.
3
Integrate velocity to position
Trapezoidal integration at 100 Hz.

2.2  15-State Error-State Kalman Filter
PART TWO · FILTERING & GPU BATCHING
Simulated IMU / GNSS corpus · 48 routes · 8.64 M rows · 8 held-out test routes
Urban navigation correction · Guo Haisu
The filter estimates the error, injects it into the nominal state, and resets — the state itself is never linearised twice.
15 error states, three each:
δp · δv · ψ · δb_a · δb_g
1 · Predict the covariance
2 · Form the GNSS correction
3 · Inject the correction and reset
Φ is rebuilt every step from the mechanization Jacobian; Q comes from the IMU noise model.
H selects position only, so S is 3×3 and the gain needs no 15×15 inverse.
Two solves and two products per step — which is why one Kalman step is launch-bound on the GPU (page 2.6).
Joseph covariance update
Kept in Joseph form so the covariance stays symmetric positive definite over 180,000 steps.

RTS RECURSION IN CONSISTENT LOCAL COORDINATES

1
Forward ESKF

2
Backward recursion
Start from the final filtered estimate; the smoother gain carries each future correction backwards.
3
Recover the full state
Attitude by quaternion multiplication, then renormalise.

2.6  Parallelism Across Windows
PART TWO · FILTERING & GPU BATCHING
Simulated IMU / GNSS corpus · 48 routes · 8.64 M rows · 8 held-out test routes
Urban navigation correction · Guo Haisu
Each window is an independent Kalman task; the batch dimension is the parallel axis.
THE BATCH, AS A MATRIX
B = 192 / windows
T = 60,000 time steps, left to right →
Inside a row the filter is strictly serial; across rows everything is independent — that is the only parallel axis, and it is enough.
01  Independent tasks
Split every log into overlapping windows; windows from different routes and vehicles share one batch. Nothing inside a window is parallel — everything across windows is.
02  Batched tensors
One batch of B windows of T samples: IMU [B, T, 3], error state [B, 15], covariance [B, 15, 15]. RTS keeps the whole state history in the same layout.
03  GPU matrix operations
At each step all B windows update together with batched products and linear solves — forward ESKF first, backward RTS after.
WHY IT PAYS   one Kalman step is a chain of 15×15 products — microseconds of work with almost no data reuse. A single step costs about 4 ms whatever the batch size: the kernel is launch-bound, not arithmetic-bound.

1

Initialize every window from nearby GNSS and run a first parallel pass.
2

Re-run each window from its predecessor's final estimate.
3
Bidirectional context
Use past and future GNSS, then discard the burn-in region from the output.
4
Overlap-add fusion
Blend overlapping outputs with normalised tent weights.

90 s

burn-in  ·  420 s of output per window  ·  burn-out
The 90 s margin is a requirement, not a knob: at 30 s, route 43's outage starts before the output boundary and the error jumps to 133 m.
ALONG A ROUTE  ·  FIVE CONSECUTIVE WINDOWS
Only the central 420 s of each window is kept; the 90 s arms are burn-in and burn-out, supplied again by the neighbouring window.

3.1  Residual Learning
PART THREE · FOUNDATION MODEL AND LoRA
Simulated IMU / GNSS corpus · 48 routes · 8.64 M rows · 8 held-out test routes
Urban navigation correction · Guo Haisu
Smoothing leaves about ten metres. The question is whether that residual is predictable from the sensors.
BASELINE
9.93 m
Mean outage error after full-route RTS on the 8 held-out routes — the number the learned corrector has to beat.
TARGET
δp = p_GT − p_KF
Three components, labelled by ground truth at every step. Never an input.
INTERFACE
p = p_KF + α · δp
δp here is the model's prediction; α is chosen on validation and may be zero — the test set never sees it.
HYPOTHESIS
the channels may carry the missing state
Motion, GNSS availability and the filter's own bias estimates: the residual depends on all three, so it might be identifiable.
THE RULE   a corrector that cannot beat predict-zero is not allowed to ship — the gate is part of the product, not an afterthought.
